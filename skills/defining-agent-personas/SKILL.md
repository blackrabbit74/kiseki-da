# Defining Agent Personas

## Purpose

Develop a coherent agent persona with identity, interaction voice, behavioral boundaries, and visual direction.

## Deliverable

Return persona text, name and identity, behavioral examples, limitations, and an avatar prompt when useful.

Done when: identity, voice, boundaries, and visual cues reinforce each other and fit the requested host format.

Stop and report when: image generation or platform write access is unavailable; deliver the usable text package and mark only that operation blocked. Continue independent work and identify the specific blocked action.

## Inputs

Audience, agent purpose, personality seeds, desired tone, host format, existing identity, and optional visual references.

## Decision rules

- Express personality through choices and examples, not adjective lists alone.
- Use tensions or imperfections without making the agent unreliable at its actual job.
- Persona boundaries must remain subordinate to real user instructions and platform constraints.

## Required procedure

1. Develop a small coherent identity from the supplied preferences.
2. Write typical and difficult interaction examples to test voice consistency.
3. Produce the requested identity files or portable text; generate imagery only through available tools when in scope.

## Constraints (set by: operator)

Do not silently activate the persona, claim human identity, or make optional avatar generation a dependency of the text deliverable. Preserve the user’s scope and existing authorization.

## Model notes

No model-specific adjustment.
