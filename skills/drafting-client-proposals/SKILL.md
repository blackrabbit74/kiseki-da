# Drafting Client Proposals

## Purpose

Give a client a concrete basis for judging whether an engagement addresses their problem.

## Deliverable

Return the client situation, desired outcome, proposal thesis, approach, scope and exclusions, deliverables, acceptance, assumptions, dependencies, and next decision.

Done when: each promised deliverable addresses a client need and each benefit or estimate has evidence, assumptions, or an explicit unresolved status.

Stop and report when: the client problem or essential engagement constraint is unknown; draft the supported portions and identify the missing premise.

## Inputs

Use discovery notes, client context, verified capabilities, relevant work evidence, commercial assumptions, and requested format.

## Decision rules

- If given a feature list, translate each relevant feature into the client’s change in work or outcome.
- If estimating value or effort, show baseline, units, assumptions, and a sensitivity range.
- If the proposal promises a result dependent on the client, identify that dependency and its owner.
- If preparing slide content, produce the argument and evidence; use available artifact tooling when a deck is actually requested.

## Required procedure

1. Frame the client’s problem and the decision the proposal should enable.
2. Connect the proposed approach to concrete deliverables and acceptance conditions.
3. Build a concise narrative with proof, limitations, and a clear next decision.

## Constraints (set by: operator)

- Do not invent client endorsements, savings, or contractual commitments, or send a proposal without authorization. Instead, provide a reviewable draft.
