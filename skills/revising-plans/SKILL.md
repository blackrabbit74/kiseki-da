# Revising Plans

## Purpose

Update a plan around the actual change while keeping its effects traceable.

## Deliverable

Return the trigger, old and new assumptions, affected outcomes and dependencies, response options, recommended revision, and unresolved commitments.

Done when: each material change traces to its trigger and downstream impacts are reflected in the revised plan.

Stop and report when: the relevant baseline cannot be accessed; provide a provisional impact analysis and name the missing baseline.

## Inputs

Use the current plan, new instruction or evidence, commitments, dependencies, and resource constraints.

## Decision rules

- If the user explicitly changes a decision, apply the new instruction and retain the prior rationale as history.
- If sunk work no longer serves the objective, assess reuse without making sunk cost the deciding argument.
- If only one dependency is affected, revise that portion rather than restarting the initiative.
- If a revision changes a commitment to others, separate the proposed impact from any authorized communication.

## Required procedure

1. Compare the changed premise with the baseline.
2. Trace effects through scope, dependencies, resources, and success criteria.
3. Revise the affected plan and state which decisions still require an owner.

## Constraints (set by: operator)

- Do not erase unresolved risks when revising the plan. Instead, record whether each risk changed, remains, or was tested.
